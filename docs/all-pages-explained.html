Login Page

/admin-login Public · No auth required
Purpose: Single entry point for both Admin and Editor users. One page with two sliding login forms — Admin on the left, Editor on the right. An orange animated panel slides across to switch between them.
State Variables
Form Data
  • adminData — { email, password } for admin form
  • editorData — { email, password } for editor form
  • errors — Yup validation errors per field
UI State
  • isEditor — false=admin panel, true=editor panel
  • showAdminPassword — show/hide admin password
  • showEditorPassword — show/hide editor password
  • loading — disables submit during API call
Functions
setCookie()
HELPER Manually writes a cookie with a calculated expiry. Used to save token and admin/editor data after login.
handleAdminChange()
HANDLER Updates adminData when user types in the admin form. Uses computed property key [e.target.name] to update the right field.
handleEditorChange()
HANDLER Same as above for editor form.
handleAdminLogin()
API (1) Clear errors. (2) Validate form with adminSchema — if invalid, show inline field errors and stop. (3) Call loginAdmin() API. (4) On success: save token cookie, show SweetAlert success, redirect to / after 1 second. (5) On API error: show SweetAlert error popup.
handleEditorLogin()
API Same flow as admin login but uses editorSchema, calls loginEditor(), and redirects to /editor.
What the User Sees
Admin form panel
Left half of the card. Email input + password input with eye toggle + Login button. Slides off-screen when switching to Editor.
Editor form panel
Right half — same structure but for editor credentials. Slides in from right when switching.
Orange slider panel
The decorative panel with icon (🛡️ or 🎓), title, description, and the "Switch to Editor/Admin" button. Covers whichever form is NOT active. Slides left/right with a 700ms CSS transition.
Inline errors
Red error messages appear directly below each input field when Yup validation fails.

Admin Dashboard

/ Admin only
Purpose: The main home page after admin login. A read-only overview with static placeholder data showing system stats, expiring licenses, institute activity, quick-action links, audit log, and user engagement chart.
Sections on Screen
Stats Grid
UI 5 StatCards: Total Institutes (25), Total Students (12,450), Active Licenses (22), Published Courses (35), Assessments Taken (8,950). Each card has a colored top border stripe and a green growth text below the number.
License Monitor
UI Shows 3 licenses expiring soon with urgency badges: red (7 days), orange (12 days), amber (19 days). A "View All License Ledgers" button sits at the bottom.
Institute Activity
UI A "Live Feed" of institutes onboarding students — shows name, student count, and timestamp. Each entry separated by a thin border.
Quick Management
UI 6 ActionCards linking to Add Institute, Issue License, Register Editor, Upload Material, Manage Curriculum, Configure Testing. On hover: orange gradient background + white text.
Audit Log
UI 4 recent system events (new institute, license renewal, curriculum update, staff added) with emoji icons and relative timestamps.
User Engagement
UI Shows total platform students (12,450), a mini bar chart of 7 bars at varying heights, and 3 metric labels: Units (1.2k), Curators (48), Tests (320).
Sub-Components (defined inside the file)
StatCard
Props: icon, title, value, sub, color. Renders a white card with a gradient stripe at top.
LicenseItem
Props: name, plan, days, date, urgency. Urgency determines badge color via a ternary chain.
ActivityItem
Props: name, sub, time. A simple row with name, subtitle, and timestamp badge.
ActionCard
Props: icon, label, link. Uses <a href>. Hover applies orange gradient via Tailwind group utilities.
AuditItem
Props: type, title, desc, time. Picks emoji from type string. Shows emoji in orange rounded box on the left.
Bar
Props: h (height string like "70%"). One bar in the engagement chart. Orange-to-amber gradient, hover fades opacity.

Institutes Page

/institutes Admin only
Purpose: Full CRUD for educational institutes. Lists all institutes in a table. The same page handles create, edit, and view in different activeTab states — no separate routes needed for edit.
State Variables
Data
  • institutes — array of all institute objects
  • courses — list of courses (for the form dropdown)
  • loading — table loading spinner
  • generatedLicenses — result from generate API (shown once)
UI / Modal State
  • activeTab — "manage" / "create" / "edit"
  • editingInstitute — institute object being edited
  • viewingInstitute — institute being viewed in modal
  • showGenerateModal — show/hide license gen modal
  • selectedInstitute — institute to generate licenses for
  • licenseCount, startDate, endDate
Functions
loadInstitutes()
API Calls getInstitutes(). Handles response shapes — tries res.data.data first, then res.data. Sets array or empty array.
loadCourses()
API Non-blocking (errors silently ignored). Fetches courses for the InstituteForm dropdown.
handleCreateSubmit()
API Calls createInstitute(data). On success: appends new institute to state array (no re-fetch needed), switches tab to "manage", shows success alert.
handleEditSubmit()
API Calls updateInstitute(id, data). On success: updates only the edited item in the array using prev.map(), switches tab back to "manage".
handleDelete()
API Shows SweetAlert confirm dialog first. If confirmed: calls deleteInstitute(id), removes item from array with prev.filter().
handleToggleActive()
API Calls toggleInstituteStatus(id). On success: flips is_active for that item in the array. Clicking the status badge in the table triggers this.
openGenerateModal()
HANDLER Sets the selected institute and resets modal fields, then shows the modal.
handleGenerateLicense()
API Validates that count ≥ 1 and both dates are set. Calls generateLicense(). On success: closes modal, stores result in generatedLicenses (which shows a one-time modal), then reloads institutes.
Table Columns
Institute Name & Code
Shows logo image (or 2-letter initials fallback), institute name in bold, and institute code in orange monospace.
Contact
Email and phone stacked vertically.
Website
Clickable link opening in new tab, or "—" if empty.
Max Students
Bold number.
Status
Clickable badge — green "Active" or grey "Inactive". Clicking calls handleToggleActive().
Actions
License button (amber) → opens generate modal. ActionButton → View (blue modal), Edit (switches to edit tab), Delete (confirm dialog).
Modals (3 total)
View Institute Modal

Shows all institute details in a 2-column grid. Logo or initials at top. Fields: email, phone, website (clickable), max students, address, status badge. Close button dismisses.

Generate License Modal

Number picker (+/− buttons or direct input) for license count. Start date and expiry date pickers. Warning: "Passwords are shown ONCE". Submit calls handleGenerateLicense().

License Result Modal (shown once)

Displays generated license keys in a table grid with key_index, license_code, user_id, password, and status columns. Warning banner: "CRITICAL — Passwords shown ONCE only." Below: full license keys list. Close button clears generatedLicenses state.

New Institute Page

/institutes/new Admin only
Purpose: Standalone form page to create a new institute. Very thin page — fetches the course list on mount and delegates all form rendering to InstituteForm. On success: shows alert and navigates back to /institutes.
useEffect
API Calls getCourses() on mount using promise chaining (.then().catch()). Errors silently ignored — form still works without courses.
handleSubmit()
API Calls createInstitute(data). On success: shows SweetAlert with 2s timer, then router.push('/institutes'). On error: shows error alert with API message.
InstituteForm
RENDER Receives courses, onSubmit, onCancel. Cancel button calls router.push('/institutes').

Editors Page

/editors Admin only
Purpose: Manage all editor accounts. Lists editors in a table with toggle-status, edit, delete, and view actions. Also has an "Assign Institutes" modal to link editors to specific institutes.
State Variables
Data
  • editors — array of editor objects
  • institutes — for the assign modal dropdown
  • loading — table loading state
Modal / Edit State
  • activeTab — "manage" / "edit"
  • editingEditor — editor object for edit form
  • viewingEditor — editor object for view modal
  • assignEditor — editor being assigned institutes
  • selectedInstituteIds — checked institute IDs in assign modal
  • assigning — loading state for assign submit
Functions
loadEditors()
API Fetches all editors, sets them in state.
loadInstitutes()
API Non-blocking. Fetches institutes for the assign modal checkboxes.
handleEditSubmit()
HANDLER Clears editing state and reloads editors from API.
handleToggleStatus()
API Calls toggleEditorStatus(id). On success: flips both is_active and status fields in the local array.
handleDelete()
API Confirm dialog → deleteEditor(id) → removes from array.
toggleInstituteSelect()
HANDLER Adds or removes an institute ID from selectedInstituteIds array based on whether it's already included.
handleAssignSubmit()
API Calls assignEditorInstitutes(editorId, ids). Updates assigned_institutes in local state. Closes modal on success.
Modals (2)
View Editor Modal

Shows editor photo/initials, full_name, email, phone, status badge, and assigned institutes count. Read-only.

Assign Institutes Modal

Scrollable checkbox list of all institutes. Each item is a <label> wrapping a checkbox — clicking anywhere on the row toggles the selection. Shows count of selected at the bottom. Save calls handleAssignSubmit().

Students Page

/students Admin only
Purpose: View and manage all enrolled students. Has a "Register Student" button that switches to the create form inline. After creation, if a generated_password is returned from the API, shows it in a one-time modal.
Key State
Data
  • students — array of student objects
  • institutes — for name lookup in table
  • createdStudent — newly created student with generated_password
UI
  • activeTab — "manage" / "create"
  • loading — table loading spinner
Functions
handleCreateSubmit()
API Calls createStudent(data). Switches tab back to "manage" and reloads list. If API returns a generated_password, stores the student in createdStudent to trigger the password modal. Otherwise shows a success alert.
handleToggleStatus()
API Flips is_active and status in local array. Clicking status badge triggers this.
handleDelete()
API Confirm dialog → delete → filter from array.
getInstituteName()
HELPER Looks up institute name by ID from the institutes array. Returns name or the raw ID as fallback.
Special: Generated Password Modal
Trigger
Appears when createdStudent state is not null — i.e., when API returns a generated_password field.
Content
Student name + enrollment number, red warning box "Password shown ONCE — save it now", large orange monospace password display.
Close
Clicking "I have saved the password — Close" sets createdStudent to null. No other way to close (intentional — forces acknowledgement).

Licenses Page

/licenses Admin only
Purpose: Accordion-style view of license keys grouped by institute. Click any institute row to expand it and load its license keys. Each key shows usage bar, expiry, and action buttons (Suspend / Activate / Expire). Clicking "View" opens a detailed modal.
Key State
Data
  • institutes — list of all institutes
  • licenseMap — { instituteId: [licenses] } — lazy loaded
  • expandedId — currently open institute row
  • viewingLicense — license object for detail modal
Loading
  • loading — institute list loading
  • licenseLoading — license ID currently processing an action
Functions
loadLicenses(id)
API Lazy loading: if licenses for this institute are already in licenseMap, just toggle the expand state. Otherwise fetch, store in map, then expand. Prevents re-fetching on every click.
handleAction()
API Generic handler for suspend/activate/expire. Uses an actionMap object to pick the right API function and labels. Shows confirm dialog with color-coded button (green for activate, red for others). After action: re-fetches all licenses for that institute.
statusColor(status)
HELPER Switch statement returning Tailwind badge classes based on license status string.
daysLeft(expiry)
HELPER Calculates days between today and expiry date: Math.ceil((new Date(expiry) - new Date()) / 86400000). Returns 0 if negative.
License Detail Modal
Header
Orange gradient. Shows key_index badge, license_code, user_id, status badge, and validity badge.
Credentials
User ID and derived seat password (extracted from user_id using regex /^(.+)-U(\d+)$/).
Dates
Start, Expiry, and Duration in a 3-column grid.
Progress Bars
Time Remaining bar (green/amber/red based on days left) and Active Sessions bar (red when full).

A 40px wide orange progress bar + percentage text.

Sessions Page

/sessions Admin only
Purpose: Real-time seat usage monitoring. Shows all institutes with their active session counts, total licensed seats, and a seat usage bar. Admins can force-reset all sessions for an institute (emergency action that kicks all logged-in students out).
State Variables
Data
  • institutes — list of institutes
  • statsMap — { id: { active, total, keys } } — computed from licenses
Loading
  • loading — initial data loading
  • resetting — institute ID currently being reset
Functions
loadData()
API (1) Fetches all institutes. (2) Uses Promise.allSettled() to fetch licenses for ALL institutes in parallel — if one fails, others still succeed. (3) Aggregates active sessions and total seats per institute into statsMap.
handleResetSeats()
API Shows confirm dialog with current active count. Calls resetInstituteSeats(id). Refreshes license data for that institute and recalculates its stats in statsMap.
totalActive / totalSeats
COMPUTED Derived by summing all values in statsMap. Shown in the 3 summary cards at the top.
Table
Usage Bar
Green (0-59%), amber (60-89%), red (90-100%). isFull shows "All seats in use" text below.
Reset Button
Disabled (grey) when active=0. Otherwise red style. Shows "Resetting…" spinner while API call runs.
Warning Banner
Bottom amber warning box explaining what Reset does and that a cron job frees expired seats every 5 minutes.

Admin Profile Page

/profile Admin only
Purpose: Admin account management. Left column: read-only profile card. Right column: two forms — Edit Profile (name, phone, photo) and Change Password.
Local Sub-Component
FormInput
COMPONENT A reusable input with optional icon on the left, and optional show/hide toggle for password fields. Uses useState(show) internally. Accepts all standard input props via {...props} spread.
State & Functions
loadProfile()
API Calls getProfile(). Populates profile, form, and profileImage state from the response.
handleUpdateProfile()
API Validates name is not empty. Calls updateProfile({ full_name, phone, profileImage }). On success: merges updated fields into profile state using prev => ({ ...prev, ...form }).
handleChangePassword()
HANDLER Client-side validation: all fields required, new=confirm match, min 6 chars. Then calls changePassword() API. Clears form on success.
Loading state
If loading is true, renders a centered spinner inside AdminLayout before returning the full profile UI.

Editor Courses Page

/editor/courses Editor only
Purpose: Full CRUD for courses in the editor panel. Also has a "Topics" assign feature — clicking the topics count badge opens a modal to assign/unassign topics to a course.
State
Data
  • courses — editor's courses (filtered: must have _id)
  • allTopics — all available topics for assignment
Modals / Edit
  • activeTab — "manage" / "create" / "edit"
  • editingCourse, viewingCourse
  • assigningCourse — for topics modal
  • selectedTopicIds — checked topics in modal
  • savingTopics — modal submit loading
Functions
loadCourses()
API Fetches editor courses. Filters result with .filter((c) => c && c._id) to remove any null/malformed entries.
openTopicsModal()
HANDLER Extracts current topic IDs from course (handles both object and string ID formats), sets them as pre-selected, opens the modal.
toggleTopic()
HANDLER Adds/removes ID from selectedTopicIds.
handleSaveTopics()
API Calls updateEditorCourse(id, { topic_ids }). Updates local state to reflect new topic count.
handleCreateSubmit()
API Handles 409 (duplicate course code) specifically — shows a tailored error message.
handleStatusToggle()
API Clicking the Active/Inactive badge calls updateEditorCourse(id, { is_active: !current }).
levelBadge()
HELPER Returns Tailwind badge classes for beginner (green), intermediate (amber), advanced (red).
Tab-based rendering
create tab
Returns early — full page replaced with CourseForm in EditorLayout. No table shown.
edit tab
Returns early — full page replaced with CourseForm pre-filled with editingCourse.
manage tab
Shows the custom grid table (not ScrollableTable — a manually built grid layout for this page).

Curriculum Page

/editor/curriculum Editor only
Purpose: Two-tab page for managing Topics and SubTopics. Tab is controlled by URL query param ?tab=topics or ?tab=subtopics. SubTopics require selecting a parent topic first. Both have search filtering and full CRUD via modals.
State
Topics
  • topics — all topics array
  • topicLoading — loading state
  • topicSearch — search input string
  • filteredTopics — memoized filtered list
SubTopics
  • selectedTopicId — parent topic for subtopics
  • subtopics — subtopics for selected topic
  • subLoading, subSearch
  • filteredSubs — memoized filtered list
Modals
  • modal — "addTopic"/"editTopic"/"viewTopic"/"addSub"/"editSub"/"viewSub"
  • target — item being edited/viewed
  • topicForm, subForm — { title, description, order }
  • saving — modal submit loading
Tab
  • tab — synced with URL param via useSearchParams
Functions
loadSubs(id)
API Resets subtopics and search, then fetches subtopics for the selected topic. Called on topic dropdown change.
openModal(type, item)
HANDLER Sets modal type and target. Pre-fills form if editing. Clears form if adding.
saveTopic()
API If target exists → update (PATCH). Otherwise → create (POST). Updates local state without re-fetching all.
saveSub()
API Same pattern. Appends topic_id: selectedTopicId to the payload so backend knows the parent.
handleDeleteTopic()
API Confirms → deletes → removes from array. Also clears selectedTopicId and subtopics if the deleted topic was selected.
Local Sub-Components
FormModal
A shared modal for add/edit of both topics and subtopics. Fields: title (required), description, order. The save button text changes between "Create" and "Update" based on modal title prefix.
ViewModal
Read-only modal showing order, title, description in slate cards with orange gradient header.

Editor Profile Page

/editor/profile Editor only
Purpose: Mirror of the admin profile page but for editors. Same layout: left card (read-only) + right forms (edit profile & change password). Key difference: photo upload uses FormData with a base64→Blob conversion for multipart upload.
Key Differences from Admin Profile
Photo upload method
API Admin uses JSON body with base64 string. Editor uses FormData: if profilePhoto starts with "data:" (base64), imports base64ToBlob() util and appends the blob to FormData. This is a multipart/form-data upload, not JSON.
Profile card data
UI Uses a .map() loop over a data array to render profile rows — more concise than Admin Profile's individual JSX blocks.
API functions
API Uses getEditorProfile(), updateEditorProfile(), changeEditorPassword() from editorPanel.js service — separate endpoints from the admin ones.
FormInput (local)
COMPONENT Identical to the one in admin profile — a copy of the same local sub-component pattern for password toggle.
