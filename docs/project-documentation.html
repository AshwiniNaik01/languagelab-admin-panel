Project Overview

What this system is and how it is organized

Language Lab Admin Panel is a full-featured web administration dashboard that allows a Super Admin to manage educational institutes, editors, students, licenses, and courses. A separate Editor Panel gives content editors the ability to create and manage language-learning materials — text modules, video modules, audio modules, vocabulary, exercises, assessments, curriculum, and games.

🛡️ Admin Role

  • Register and manage institutes
  • Create and manage editors
  • Manage student accounts
  • Issue and track licenses
  • View and manage courses
  • Access analytics & reports
  • Manage sessions and content
  • View system audit log

🎓 Editor Role

  • Create & manage courses
  • Author text learning modules
  • Upload video/audio modules
  • Build exercise modules
  • Create vocabulary modules
  • Design assessments
  • Plan curriculum
  • Manage educational games

Authentication Flow

How login, tokens, and route protection work
Two separate roles, one login page. The login page shows an Admin form by default. A sliding panel lets users switch to the Editor form. Each submits to a different API endpoint and stores its token under a different cookie key.

Admin Login Flow

User enters email + password
→
Yup schema validates fields
→
POST /admin/login (API)
→
Token stored in token cookie
→
Redirect → / (Dashboard)

Editor Login Flow

User enters email + password
→
Yup schema validates fields
→
POST /editor/login (API)
→
Token stored in token cookie
→
Redirect → /editor

Middleware Route Protection

middleware.js runs on every request to protected routes. It checks for a token or editor_token cookie. If neither is present the user is redirected to /admin-login.

Protected routes: /editor, /institutes, /students, /editors, /licenses, /courses, /sessions, /analytics, /content, /profile

Admin Pages — Detailed Breakdown

Every page in the admin panel explained one by one

1. Login Page

/admin-login

The entry point for the entire platform. A single page with two login panels (Admin and Editor) that slide in/out. A gradient orange panel acts as a switcher — clicking "Switch to Editor" slides the form panel to reveal the Editor login form, and vice versa. No navigation sidebar is shown on this page (it is public).

●Admin email + password form
●Editor email + password form
●Animated slide transition between forms
●Show/hide password toggle (eye icon)
●Yup client-side validation (inline errors)
●SweetAlert2 success/error feedback
●Token saved to cookie on success
●Redirect to dashboard after login
File: app/admin-login/page.js — uses loginAdmin() and loginEditor() from app/services/admin-login.js

2. Dashboard (Home)

/

The main landing page after admin login. Shows a high-level system overview at a glance — statistics, license monitor, institute activity feed, quick action shortcuts, audit log, and a user engagement bar chart. All wrapped inside AdminLayout which provides the sidebar and top navbar.

●Stats: Institutes, Students, Licenses, Courses, Assessments
●License Monitor — expiring licenses with urgency badges
●Institute Activity — live onboarding feed
●Quick Management — 6 action shortcut cards
●Recent Audit Log — system events timeline
●User Engagement — mini bar chart widget
Files: app/page.js → renders app/components/Dashboard.jsx inside app/layouts/AdminLayout.jsx

3. Institutes List

/institutes

Displays all registered educational institutes in a data table. Admins can browse, search, and manage institutes. Each row has action buttons (edit, view, delete). An "Add Institute" button links to the create form.

●Paginated data table (reusable Table component)
●Institute name, location, license status columns
●Action buttons per row (edit / delete)
●Empty state when no institutes exist
●Table skeleton loader while fetching

3b. New Institute

/institutes/new

A form page to register a new educational institute. Uses InstituteForm component with logo upload, text fields, dropdowns for state/city, and toggle switches. Validates all fields with Yup before submitting to the API.

●Logo file uploader
●Institute name, address, city, state fields
●Contact email and phone
●Yup validation with inline errors
●Submit → POST to API → success alert → redirect

4. Editors List

/editors

Lists all content editors registered in the system. Shows their name, email, assigned institute, and status. Admins can create new editors or deactivate existing ones.

●Full list in data table
●Name, email, institute, active status
●Edit / delete per row
●Add New Editor button

4b. New Editor

/editors/new

Form to create a new editor account. Uses EditorForm and validates with neweditor.schema.js. Assigns the editor to an institute and sets their initial password.

●First name, last name, email
●Institute dropdown (fetched from API)
●Password and confirm password
●Yup validation + error display

5. Students List

/students

A table of all students enrolled across institutes. Admins can view, filter, and manage student records. Includes bulk operations and export capabilities.

●Student name, email, institute, enrolment date
●Search / filter by institute
●Row-level edit and delete actions
●Loading skeleton while data fetches

5b. New Student

/students/new

Form to manually register a student. Uses StudentForm and student.schema.js. Associates the student with a specific institute.

●Full name, email, phone
●Institute dropdown
●Password fields
●Validation and success redirect

6. Licenses List

/licenses

Shows all license agreements issued to institutes. Each license has a type (Basic, Standard, Premium), an expiry date, and an assigned institute. Licenses with near-expiry dates are highlighted on the dashboard.

●License key, type, institute, expiry date
●Status badges (active / expiring / expired)
●Renew / delete actions
●Add New License button

6b. New License

/licenses/new

Form to issue a new license to an institute. Uses LicenseForm and validates with newlicenses.schema.js.

●Institute dropdown
●License type selection
●Start date and expiry date pickers
●Max students count

7. Courses (Admin View)

/courses

Admin view of all published courses across the platform. Admins can review courses created by editors, view their modules, and manage course visibility. Uses the shared CoursesContent component.

●Course name, institute, module count
●Published / draft status toggle
●Filter by institute
●Delete / view details actions

7b. New Course (Admin)

/courses/new

Form to create a new course from the admin side. Uses CourseForm and course.schema.js.

●Course title and description
●Language and level selection
●Institute assignment
●Thumbnail image upload

8. Analytics

/analytics

Analytics and reporting dashboard showing platform-wide usage statistics. Displays Chart.js graphs for student activity, course completions, assessment scores, and institute engagement over time.

●Student enrollment trends (line chart)
●Course completion rates (bar chart)
●Assessment score distribution
●Institute-wise activity breakdown
●Date range filter
●Export data option

9. Content Management

/content

Central content management page for uploading and organizing learning materials. Admins can upload resources, manage file organization, and configure material availability per institute.

●File/material listing
●Upload new material
●Filter by type / institute
●Enable / disable per institute

10. Sessions

/sessions

Session management and configuration page. Admins can view active testing sessions, configure assessment windows, and track student session activity across institutes.

●Active and scheduled sessions list
●Create new session / assessment window
●Session start/end times
●Institute and course assignment

11. Admin Profile

/profile

Admin account profile page. Allows the logged-in admin to view and update their personal information, change their password, and manage account settings.

●Name, email display and edit
●Change password form

Editor Panel — Detailed Breakdown

All pages available to editors after login
The Editor Panel is a completely separate UI from the Admin Panel — different sidebar, different navbar (EditorLayout), and different API service calls. An editor only sees and manages content for their assigned institute.

12. Editor Dashboard

/editor

The home page for editors after login. Displays a summary of the editor's assigned courses, recent module activity, quick links to create new content, and basic statistics relevant to their content library.

●Assigned courses count
●Total modules created
●Recent activity feed
●Quick create buttons

13. Editor Courses

/editor/courses

Shows courses owned/created by the logged-in editor. Each course lists its title, language, level, and module count. Uses the shared CoursesContent component but scoped to the editor's institute.

●Course cards with module counts
●Published / draft toggle
●Edit and delete per course
●Create new course button

13b. New Course (Editor)

/editor/courses/new

Editor-facing course creation form. Uses the shared NewCourseContent component and course.schema.js. The course is automatically linked to the editor's institute.

●Course title, description, language, level
●Thumbnail image upload
●Tags / category multi-select
●Auto-linked to editor's institute

14. Content Modules (5 Types)

/editor/modules/[type]

Editors can create five types of learning modules. Each type has its own list page and a separate creation form. All module list pages use the generic ModuleTypePage wrapper component.

14a. Text Module /editor/modules/text

Rich text-based lessons. Editors write or paste article-style learning content with headings, paragraphs, images, and formatting. Uses TextModuleForm.

●Title and lesson body
●Rich text editor
●Course and level assignment
●Ordering within course
14b. Video Module /editor/modules/video

Video-based lessons. Editors upload or link video content with a title, description, and transcript. Uses VideoModuleForm.

●Video file upload / URL
●Title and description
●Transcript / captions
●Duration and thumbnail
14c. Audio Module /editor/modules/audio

Audio-based listening lessons. Editors upload pronunciation guides, dialogues, or narrated content. Uses AudioModuleForm.

●Audio file upload
●Title and description
●Script / transcript text
●Speaker information
14d. Exercise Module /editor/modules/exercise

Interactive exercises — MCQs, fill-in-the-blanks, matching, and ordering questions. Uses ExerciseModuleForm.

●Exercise type selection
●Question and answer builder
●Correct answer marking
●Points / scoring config
14e. Vocabulary Module /editor/modules/vocabulary

Vocabulary flashcard-style modules. Editors add words, definitions, example sentences, and audio pronunciations. Uses VocabularyModuleForm.

●Word and definition pairs
●Example sentences
●Audio pronunciation upload
●Part of speech tagging

15. Assessments

/editor/assessments

Editors create and manage formal assessments (tests and quizzes). Assessments are linked to courses and can be scheduled with time windows. Results feed into the admin analytics dashboard.

●Assessment list with status
●Create new assessment
●Question bank management
●Schedule / time window setting
●Passing score configuration
●View results and submissions

16. Curriculum

/editor/curriculum

Curriculum planning and organization page. Editors can arrange modules into a structured learning path, set prerequisites, and define the order in which students should progress through content.

●Drag-and-drop module ordering
●Unit / chapter grouping
●Prerequisites setup
●Completion criteria per unit

17. Games

/editor/games

Gamification management page. Editors configure and assign educational games to reinforce vocabulary, grammar, and language comprehension in an interactive, engaging format.

●Game type catalog
●Configure game parameters
●Assign games to courses
●Leaderboard settings

18. Editor Profile

/editor/profile

Profile page for the logged-in editor. Allows updating personal details, changing password, and viewing assigned institute information.

●Name and email edit
●Change password
●Assigned institute info
●Account settings

Services & API Layer

course.jsCRUD for courses — get all, get by editor, create, update, delete

Middleware

Route-level authentication guard

middleware.js (Next.js Edge Middleware) intercepts every request before it reaches a page. It checks the list of protected routes and, if the request matches one, verifies that a token or editor_token cookie is present. If not, the user is immediately redirected to /admin-login.

Protected Path PatternWho accesses it
/editor/*Editors only
/institutes/*Admin
/students/*Admin
/editors/*Admin
/licenses/*Admin
/courses/*Admin
/sessions/*Admin
/analytics/*Admin
/content/*Admin
/profile/*Admin & Editor

Validation Schemas

Yup-based form validation across the platform
Every form validates locally with Yup before any API call is made. Errors are displayed inline beneath each field. When abortEarly: false is set, ALL field errors appear at once rather than stopping at the first failure.
Schema FileUsed ByKey Rules
admin.schema.jsAdmin Login formEmail format, password min 6 chars
editor.schema.jsEditor Login formEmail format, password required
neweditor.schema.jsCreate Editor formName, email, password, confirm password match, institute required
institute.schema.jsCreate/Edit Institute formName required, valid email, phone pattern
student.schema.jsCreate/Edit Student formName, email, phone, institute required
course.schema.jsCreate/Edit Course formTitle required, language and level required
newlicenses.schema.jsCreate License formInstitute, type, start and expiry dates, max students
validations/moduleSchemas.jsAll 5 module formsTitle required, course required, type-specific field rules
